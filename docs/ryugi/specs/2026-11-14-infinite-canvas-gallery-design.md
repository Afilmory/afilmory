# 无限画布画廊 · 设计稿

日期:2026-11-14
状态:用户已批准(2026-11-14)
范围:`apps/web`(画廊 SPA)+ 一个新的引擎包。不涉及 `be/`、`apps/ssr`、`apps/mobile`、`packages/builder`。

标注约定:**[用户]** 是用户明确定的;**[我定]** 是写稿人替用户定的默认值,用户审稿时可以推翻;**[交给实现]** 是留给实现者判断的。

## 1. 意图

现有画廊只有两种看法:瀑布流和列表,都是从上往下滚。用户想加第三种:照片铺在一个可以自由拖动、缩放的平面上,用 WebGL 渲染。

它要补的是两件瀑布流做不到的事:

- **漫无目的地逛。** 四个方向都拖不到头。
- **一眼看全,再钻进去。** 缩小能看到整个相册按月份(或相机、标签、地点)聚成的全貌,放大进入某一组。

画布是访客主动切过去的展示方式,不替代瀑布流。默认视图仍是瀑布流。**[我定]**

## 2. 目标 / 非目标 / 反目标

**目标**

- 一块画布,五种排布:漫游(无尽照片墙)、月份、相机、标签、地点。**[用户]**
- 切换排布时,照片从旧位置飞到新位置。**[用户]**
- 10,000 张照片下,在近几年的集显笔记本、1440p 窗口里拖动和缩放保持 60fps。**[用户定规模,我定机型]**
- 点击照片用现有 Viewer 打开,带和瀑布流一致的共享元素过渡。**[我定]**
- 跟随现有筛选(标签、相机、镜头、评分、日期范围)和排序。**[我定]**
- 桌面(≥`lg`)有入口;触屏手势(单指拖、双指缩放)完整实现,服务触屏笔记本和横屏平板。**[用户]**

**非目标**

- 小屏(`lg` 断点以下,<1024px)上的画布。小屏的视图切换在 `PageHeaderRight.tsx` 的 `lg:hidden` 下拉菜单里(瀑布流/列表),这次不往里加画布项;小屏的 chrome 布局另开一份设计。**[用户]**
- WebGPU 后端。只做 WebGL2。**[用户]**
- 让构建器产出更小的缩略图。画布只用现有的 600px 宽缩略图和清单里的 thumbhash。
- 50,000 张以上的规模。
- 画布上的 EXIF 悬浮层、Live Photo 悬停播放、评论/反应入口。照片本身就够了,细节点开再看。**[我定]**
- 用户自己摆放照片、保存布局。

**反目标**(做成这样算失败)

- 分组排布缩到“装下全部”时发出缩略图请求。这个视角必须零请求。(漫游在最小缩放下照片仍有约 120px 宽,允许请求,由 §6.4 的调度限速。)**[我定]**
- 画布上出现转圈。占位只用 thumbhash。
- 画布的 chrome 抢了照片的注意力。DESIGN.md 的原则是"照片是唯一的光源"。
- 没有 WebGL2 或上下文丢失时出现白屏或报错页。

## 3. 约束

- `apps/web` 必须同时在静态/SSR 流程和后端流程里工作,不能假设后端存在。数据只走 `useContextPhotos()` / `photoLoader`。
- 缩略图可能跨域。用户已确认线上缩略图带 CORS 头。**[用户]** 仍要处理自托管用户存储没配 CORS 的情况(见 §9)。
- UI 遵守根目录 `DESIGN.md`:UIKit 语义色、`bg-material-*` + `backdrop-blur-*` + 发丝边框 + 按容器尺寸选圆角;空间运动用 `Spring` 预设;z-index 只用两层体系;图标用 `i-mingcute-*`;暗色唯一。
- 仓库规则:零注释、零 JSDoc;文件不超过 500 行,React 组件不超过 300 行;不加 feature flag 或兼容垫片;页面是薄路由壳,逻辑在 `modules/<domain>/`。
- i18n:先改 `locales/app/en.json`,再补 `zh-CN, zh-HK, zh-TW, jp, ko`;键是扁平的点分键,同一个键不能既是叶子又是父路径。
- 不能用裸的全局 `location`,用 `useLocation()` 或 `getReadonlyRoute()`。
- `motion` 版本被 pin 住,不升级。

## 4. 用户看到什么

### 4.1 进入

页头的视图切换多一个图标(瀑布流、列表、**画布**)。浏览器不支持 WebGL2 时这个图标不出现。**[我定]**

窗口宽度在 `lg` 以下时画布不可用:图标不出现,URL 带 `view=canvas` 时显示瀑布流,窗口从宽缩到窄时也切回瀑布流。画布的 chrome 因此只需要桌面布局。**[用户]**

切到画布后:

- 画布占满视口,`fixed`,在页头之下。页头照常浮在上面,带原有的顶部渐隐。
- 瀑布流内容、`PageFooter`、`ActiveFiltersHero` 不渲染。筛选仍可通过页头的搜索/筛选入口修改。**[我定]**
- 页面本身不滚动。

### 4.2 排布

底部居中一个玻璃分段控件:**漫游 · 月份 · 相机 · 标签 · 地点**。**[我定:把"漫游/时间"切换和分组维度合并成一个控件]**

- 当前筛选结果里没有任何照片带该维度数据时,该项不显示。例:没有一张照片有 `location`,就没有"地点"。
- 默认是漫游。

**漫游(无尽照片墙)** — 画板 `q1-wall`

- 等宽列的瀑布流,每列纵向独立循环,横向按列数循环。四个方向永远拖不到头。
- 照片少时,同一张照片会在不同列重复出现,保证一屏内不出现明显的重复图案(原型做法:18 张照片铺 9 列,每列 6 张,相邻列错开)。照片多时每张只出现一次。循环周期至少是"平面最小缩放(20%)下视口尺寸的 2 倍"。**[我定]**
- 顺序跟随当前排序。

**分组(月份 / 相机 / 标签 / 地点)** — 画板 `q1-islands`

- 每组是一座"岛":组内照片排成小瀑布流,左上方是组名(`text-sm` 加粗)和一行次要信息(`text-xs text-text-secondary`,例:"7 张 · X-T5")。
- 岛之间留白明显大于岛内间距。
- 有边界:拖到边缘会停住。
- 岛的摆放 **[我定,原型只验证了 8 座岛的情况]**:按组的顺序做行式排布(一行放满换行),整体宽高比接近视口。月份按时间倒序(跟随排序方向),其余维度按照片数从多到少。原型里连接各岛的虚线不做。
- 分组键:
  - 月份:`dateTaken` 的年-月。显示为 `2025 · 05`。
  - 相机:`exif.Make + exif.Model`,和现有相机筛选用同一个显示名。
  - 标签:`tags`。一张照片有多个标签时,出现在每个标签的岛里。
  - 地点:`location.city`,没有 city 用 `location.country`。
  - 缺数据的照片归到一座排在最后的岛("未标注"/"未知相机"/"未知地点")。
- 右下角有小地图(玻璃面板):显示所有岛的轮廓和当前视口框;点击或拖动小地图移动视口。只在分组排布下出现。
- 双击岛名或岛内空白:视口飞到刚好装下这座岛。
- 缩小到岛名会互相重叠时,按照片数从少到多隐藏岛名。**[我定]**
- 任何维度最多 60 座岛。超出时保留照片数最多的 59 组,其余合并成一座“其他”岛,排在缺数据的岛之前。月份超过 60 个时改为按年分组。**[我定]**

**切换排布**

- 每张照片从当前位置飞到新位置,同时相机飞到新排布的初始视角。用 `Spring.presets.smooth` 的参数(时长 0.4s,无回弹)。**[我定]**
- 漫游里同一张照片有多个副本时,离视口中心最近的那个副本负责飞,其余副本淡出。反方向同理:目标位置取离视口中心最近的副本,其余淡入。
- 进入分组排布的初始视角是"装下全部";进入漫游的初始视角是 100% 缩放。
- 系统开了"减少动态效果"时,不飞,改为 200ms 淡入淡出;拖动惯性也关掉。

### 4.3 操作

| 输入 | 效果 |
| --- | --- |
| 鼠标/单指拖动 | 平移,松手有惯性 |
| 滚轮 / 触控板双指滑动 | 平移 |
| ⌘/Ctrl + 滚轮、触控板捏合 | 以光标为中心缩放 |
| 双指捏合(触屏) | 以两指中点为中心缩放 |
| 方向键 | 平移 |
| `+` / `-` | 缩放 |
| `0` | 分组排布:装下全部;漫游:回到 100% |
| 点击照片(没有拖动) | 打开 Viewer |
| 悬停照片 | 发丝边框变亮,左下角玻璃胶囊显示"日期 · 相机" |

右下角有缩放控件(− / 百分比 / +)。

缩放范围:

- 上限:照片在屏幕上的长边不超过其缩略图像素的 1.5 倍(按 `devicePixelRatio` 换算)。再大就该点开。**[我定]**
- 下限:漫游的平面墙到 20% 为止,再缩小墙面收成一卷**胶片长卷**,10% 时收完(即漫游下限)。分组和色谱是"装下全部"再小 15%,永远是平面。
- 胶片长卷(画板 `canvas-zoom-out-directions` 的 `dir-film`,替换了早先的球形方案,球形代码存于分支 `archive/canvas-globe`):
  - 每张照片只出现一次,从旧到新排开;收卷前屏幕中心那张成为中间帧,其余帧按与中间帧的距离依次飞入,墙面淡出。
  - 20% 以下缩放固定以屏幕中心为锚点。
  - 收卷过半后,拖动 / 横向滚动改为在时间里滚动底片(带惯性),停在首帧或末帧居中处;摄像机不动。
  - 点帧直接打开查看器。收卷开始后不再响应"按住聚拢"。
  - 放大离开底片时,墙面先移到中间帧那张照片最近的副本上,再展开。
  - 片基和齿孔是 canvas 下面的 DOM,边码、日期、相机、换月标签是叠在上面的 DOM;照片仍由 WebGL 绘制。

首次进入时底部分段控件上方显示一行操作提示,第一次拖动后淡出,本次会话不再出现。**[我定]**

### 4.4 打开照片

- 点击照片调用现有的 `photoViewer.openViewer(index, triggerEl)`。
- Viewer 的共享元素过渡需要一个 DOM 元素作为起点和终点。画布提供一个不可见的代理 `div`,带 `getViewerTransitionTriggerProps(photoId)`,定位在该照片在屏幕上的矩形。
- Viewer 关闭时会用 `[data-…="当前照片 id"]` 重新查找终点(见 `packages/viewer-motion/src/trigger-utils.ts`)。所以在 Viewer 打开期间,当用户切到别的照片时,代理元素要跟着换成那张照片的 id 和屏幕矩形;那张照片不在视口里时,不渲染代理元素(Viewer 会走它已有的无终点退场)。
- Viewer 打开期间画布停止渲染循环。

### 4.5 URL

视图和排布写进 URL 查询参数,可以分享:`?view=canvas&arrange=wall|month|camera|tag|location`。**[我定]** 相机位置和缩放不进 URL。

现状:`viewMode` 只存在 `gallerySettingAtom` 里,不在 URL。本设计只要求画布模式进 URL;要不要顺手把 `masonry`/`list` 也搬进 URL **[交给实现]**。

## 5. 视觉方向

- **产品:** 摄影师个人相册的访客,在桌面浏览器里用鼠标或触控板闲逛。
- **气质:** 失重、安静、暗房里的看片台。
- **世界:** 看片台、印样、展墙。背景就是 `--color-background`,照片是唯一发光的东西。
- **时刻:** 两个地方值得花力气——松手后的惯性滑行,和切换排布时照片的集体迁移。
- **签名:** 不新增。沿用系统的玻璃配方。

已接受的视觉选择:

- 照片圆角约 6px(随缩放缩小),1px `white/10` 发丝边框,悬停 `white/55`。
- 所有浮层用标准配方:`bg-material-medium` + `backdrop-blur-2xl` + `border-accent/20` + `rounded-xl`,阴影用 DESIGN.md §3.4 的三层淡阴影。
- 没画过、但用户没选的 C 方案(倾斜、景深)的任何元素都不要带进来。

## 6. 架构

```
apps/web/src/modules/gallery/canvas/     React 壳:挂载、chrome、URL、Viewer 交接
packages/photo-canvas/                   引擎:与 React 无关
  camera        视口状态、惯性、飞行、缩放限制
  layouts/      纯函数:照片 → 位置
  renderer      WebGL2 实例化绘制
  textures      两级纹理、LRU、请求调度
  input         指针/滚轮/触摸/键盘 → 相机
```

新包名 `@afilmory/photo-canvas` **[我定,可改名]**。拆包的理由:和 `packages/webgl-viewer`、`packages/viewer-motion` 一样,引擎不认识 React,布局和相机数学可以用 `node:test` 单测。

React 壳和引擎的边界:

- 壳传入:`photos`(已筛选排序)、`arrange`、容器元素、`onPhotoClick(photoId, screenRect)`、`onHover(photoId | null)`。
- 引擎暴露:`getScreenRect(photoId)`(给代理元素用)、`flyTo(...)`、`pause()/resume()`、`destroy()`,以及每帧的相机状态订阅(给小地图、缩放读数、岛名标签用)。
- 岛名标签和小地图是 DOM,不在 WebGL 里画。标签用 `transform` 每帧定位,只渲染视口内的。理由:要走 i18n 和设计系统的字体/颜色。

### 6.1 布局(纯函数)

- `wallLayout(photos, { columnWidth, gap })` → 列定义(每列的照片序列、周期、错位)。可见实例由相机视口每帧解析计算,不预先展开。
- `groupedLayout(photos, keyFn, { columnWidth, gap, viewportAspect })` → 岛列表(包围盒、组名、成员位置)和总边界。
- 两者都只依赖 `aspectRatio`,不测量图片。

### 6.2 渲染

- 一个 WebGL2 上下文,实例化矩形。每个实例:位置、尺寸、纹理坐标/层、透明度、两级纹理之间的混合系数。
- 圆角和边框在片元着色器里做。
- 性能目标按**照片数**算:10,000 张。实例数可以更多——标签排布里一张照片出现在它每个标签的岛里,按 40,000 个实例做预算。
- 分组排布的实例位置不随相机变化,实例缓冲区在布局算好后一次写入,平移缩放只改相机 uniform;只有排布切换的飞行期间逐帧更新。漫游的实例由视口每帧解析生成,数量只和视口有关。
- 没有需要重画的东西时(相机静止、无动画、无纹理到达)不提交帧。

### 6.3 纹理:两级

这是 10,000 张能跑起来的关键。

| 级别 | 来源 | 何时使用 | 网络 |
| --- | --- | --- | --- |
| 占位级 | 清单里的 `thumbHash`,解码成约 32px 的小图,全部打进图集 | 始终可用;照片在屏幕上长边小于约 48 CSS 像素时只用它 | 无 |
| 缩略图级 | `thumbnailUrl`(600px 宽),按屏幕尺寸降采样到 128 / 256 / 512 三档后上传 | 照片在屏幕上长边 ≥ 约 48 CSS 像素时;视口内照片不超过 600 张时不设这个门槛,再小也加载 128 档 | 有 |

- 占位级:10,000 × 32×32 可以放进一张 4096² 纹理。解码分帧进行(或放 worker),不阻塞首帧;没解码完的先用纯色。没有 `thumbHash` 的照片用 `fill` 色。
- 缩略图级:`fetch(url, { mode: 'cors', signal })` → `createImageBitmap(blob, { resizeWidth… })` → 上传。解码放 worker **[交给实现:是否复用 `webgl-viewer` 的 worker 模式]**。
- 缩略图到达时在 200ms 内从占位级淡入。
- 档位阈值、图集具体怎么组织(纹理数组还是多张图集)**[交给实现]**。

### 6.4 显存和请求

- 缩略图级有字节预算,LRU 淘汰离开视口最久的。默认预算桌面 256MB,`navigator.deviceMemory ≤ 4` 时 128MB。**[我定]**
- 请求调度:
  - 并发上限 6。
  - 优先级按到视口中心的距离。
  - 照片滑出视口(含缓冲)时用 `AbortController` 取消还没完成的请求。
  - 相机高速移动时(惯性滑行、飞行中)不发新请求,速度降下来再发。
- 已知代价:中等缩放下一屏可能有 100–200 张照片各需要一张 100–500KB 的缩略图。靠"高速移动不请求"和浏览器 HTTP 缓存缓解;不在本设计里解决。

## 7. 状态

- `GalleryViewMode` 增加 `'canvas'`。
- 排布(`arrange`)是画布专属状态,放在 `modules/gallery/canvas/` 里就地的 Jotai atom,并和 URL 同步。
- 相机状态只在引擎里,不进 React 状态。切到别的视图再切回来,相机复位。**[我定]**
- 筛选或排序变化时:重新计算布局,照片飞到新位置(复用排布切换的过渡);被筛掉的淡出,新出现的淡入。

## 8. 无障碍

- 画布是 `<canvas>`,读屏无法逐张导航。瀑布流和列表仍是可访问的默认路径;画布元素带 `aria-label` 说明这是一个可视化浏览视图。
- 所有 chrome 控件(分段控件、缩放按钮、小地图)可键盘聚焦,用 `focusRing`,有可访问名称。
- 键盘操作见 §4.3。
- 尊重 `prefers-reduced-motion`(见 §4.2)。

## 9. 降级

| 情况 | 行为 |
| --- | --- |
| 没有 WebGL2,或窗口宽度在 `lg` 以下 | 视图切换里不出现画布图标;URL 带 `view=canvas` 时回落到瀑布流 |
| 某张缩略图请求失败(含 CORS 失败) | 该照片停在占位级,不重试风暴(同一张最多重试 1 次),仍可点击打开 |
| `webglcontextlost` | 停止渲染;`webglcontextrestored` 后重建着色器和占位图集,缩略图按需重新请求 |
| 筛选结果为空 | 显示和瀑布流一致的空状态 |
| 照片数为 1–2 张 | 漫游照常循环(会看到重复);分组照常 |

## 10. 测试和验收

单测(`node:test` + `tsx`,和 `packages/viewer-motion` 同一套):

- `wallLayout`:给定视口,返回的可见实例覆盖视口且不重叠;周期满足"至少 2 倍视口";少量照片时相邻列不出现同一张照片并排。
- `groupedLayout`:岛不重叠;缺数据的照片进入末尾的岛;多标签照片出现在每个标签的岛里。
- 相机:以某点为中心缩放后该点的世界坐标不变;缩放限制;分组排布的边界夹取。
- 纹理调度:优先级顺序、并发上限、滑出视口取消、LRU 在预算内。

在浏览器里验收(真实运行,截图或录屏):

1. 页头出现第三个视图图标,点击进入画布。
2. 漫游下向四个方向各拖动一次,都不见边界。
3. 切到"月份",照片飞成岛;切回"漫游",照片飞回墙。
4. 清空缓存后直接打开 `?view=canvas&arrange=month`(初始视角是装下全部),网络面板里没有缩略图请求。
5. 点击一张照片,Viewer 从该照片的位置展开;在 Viewer 里切到下一张再关闭,收回到下一张的位置。
6. 加一个标签筛选,画布只剩筛出的照片。
7. 复制带 `?view=canvas&arrange=month` 的 URL 到新标签页,直接进入月份排布。
8. 用生成的 10,000 张假数据(重复现有缩略图即可)跑一次拖动和缩放,记录帧率。
